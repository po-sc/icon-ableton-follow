# iCON V & P Series Ableton + Follow

Добавляет к официальному Ableton-скрипту iCON v1.16 слежение за выбранной дорожкой: выделил дорожку в Live, и она становится первой на контроллере, а следующие идут за ней. Цвета, режимы, экраны и экстендеры остаются от оригинала.

Поддержка по документации iCON: V1-M, V1-X, P1-M, P1-X, P1-Nano.

**[Скачать готовый архив](https://github.com/po-sc/icon-ableton-follow/releases/latest)** · **[Инструкция по установке](INSTALL.md)**

## Что хранится в репозитории

В коде репозитория скрипта iCON нет: только сборщик с правками, тесты и инструменты. Из кода iCON в сборщике есть лишь короткие строки, по которым он находит места для правок.

Готовый архив с кодом iCON лежит в Releases. В архиве iCON нет лицензии, на сайте указано «All rights reserved», поэтому репозиторий приватный. Перед тем как сделать его публичным, этот релиз нужно удалить.

## Сборка

Официальный архив скачивается [со страницы контроллера](https://iconproaudio.com/product/p1-nano/).

```bash
python3 build.py Icon-V-and-P-Series-Ableton-Script-v1.16-ZIP.zip
```

Рядом с архивом появится `Icon-V-and-P-Series-Ableton-Script-v1.16-Follow.zip`. Если iCON изменит файлы в новой версии, сборка остановится и покажет место, где правка не подошла.

## Цвета на экране

Цвета шлёт официальный код iCON, Follow их не меняет: `F0 00 02 4E 16 14` + 8×RGB + `F7`. Они обновляются при старте, Bank, смене выбранной дорожки и смене цвета в Live.

Производитель заявляет цвет дорожки для внешнего экрана D5, а для встроенного экрана P1-Nano только имя, значения и метры. Покажет ли его конкретный экран, проверяет `color_test`.

## Что изменено

| Изменение | Причина |
|---|---|
| Слежение за дорожкой, `v1_core/track_follow.py` | Основная функция |
| Сдвиг банка на следующем тике | Listener срабатывает синхронно, и Select подсвечивал не тот канал |
| Сброс сдвига при входе в Return | У Return свой короткий список, каналы оставались пустыми |
| Выбранная дорожка удерживается при добавлении и удалении дорожек | Если банк не сдвигали вручную |
| Bank останавливается на последней дорожке | В оригинале можно было уйти в пустоту без ограничения |
| Listener'ы снимаются при отключении | В оригинале старый экземпляр продолжал реагировать на Live |
| Убран кэш цветов в Send | При повторном входе оставались цвета дорожек |
| Mute, Solo и Rec обновляются при изменении состава дорожек | В оригинале индикаторы оставались от прежних дорожек |
| Красные часы показывают `001.01.01.000`, как штатный Mackie | В оригинале двоеточия выглядели как чёрточки, а часть цифр была погашена |

Экстендеры не обмениваются сообщениями о выборе: каждый блок сам слушает Live и прибавляет свой слот, поэтому блоки всегда идут подряд.

## Проверка

```bash
python3 -B test/harness.py build Icon_V_and_P_Series_Ableton_Follow     # сценарии
python3 -B test/fuzz.py build 1 x+m+x+x 300                             # случайные действия
python3.11 -B test/real_framework.py build                              # настоящий _Framework из Live 12
```

Для `real_framework.py` нужны Python 3.11 и Live 12 Suite в `/Applications`.

Тесты используют макет Live API. `real_framework.py` запускает скрипт поверх настоящего `_Framework.ControlSurface` из установленного Live 12, но сам Live API там тоже макет.

**На реальном Ableton и контроллере скрипт ещё не проверялся.**

## Инструменты

Обе утилиты только для macOS.

- `swift tools/color_test.swift` показывает на контроллере 8 цветов и надписи `P1 CH 1..8` без Ableton. Шлёт во все порты iCON, цифра после `P` показывает порт активного слота. Перед запуском закрыть Ableton.
- `tools/p1watch.swift` только слушает порты и пишет в лог, когда контроллер отключается от USB и возвращается. Зависание без отключения от USB он не определяет.

## Если что-то не работает

Причину покажет `Log.txt` в `~/Library/Preferences/Ableton/Live <версия>/`. На одном порту должен быть выбран только один скрипт, так что `MackieControlFollow` и эта версия одновременно работать не будут.
